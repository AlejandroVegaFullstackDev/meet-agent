# ADR-0009: Servidor MCP por stdio; la app es dueña de la captura y del consentimiento
**Estado:** aceptada · 2026-10-15
**Contexto:** cada persona usa su propia IA (Claude, Codex, DeepSeek…). MCP es el estándar que todas soportan.
**Decisión:**
- `MeetAgent.Mcp` con el SDK oficial `ModelContextProtocol` 2.2.0, transporte stdio y 7 herramientas en español.
- Lecturas directas a la SQLite (WAL): funcionan aunque la app esté cerrada, y "en vivo" usa un cursor por id de segmento.
- Empezar y terminar van a la app de escritorio por `MeetAgent.Control`: una línea JSON sobre named pipe o socket Unix con `PipeOptions.CurrentUserOnly`. Solo la app captura audio. **Empezar abre el diálogo de consentimiento de la app**: el protocolo no tiene ningún campo para grabar, y una prueba lo verifica.
**Alternativas descartadas:**
- Que el MCP capture audio: sin UI no hay consentimiento visible, y serían dos procesos peleando por el micrófono.
- *Elicitation* de MCP: no todos los clientes la implementan, y el consentimiento debe vivir en la app, no en el chat de la IA.
